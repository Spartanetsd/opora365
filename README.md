# ОПОРА 365 · Obsidian Flow

Особиста операційна система дня для iPhone. Встановлюється на початковий екран, працює без інтернету після першого запуску, усі дані зберігаються лише на пристрої.

Головний принцип: за три секунди видно, що відбувається, яка наступна дія і чи все під контролем. Кожен індикатор показує лише реальні дані — жодних «відсотків готовності» чи декоративних графіків.

## Що всередині

| Розділ | Що робить |
|---|---|
| **Сьогодні** — Living Dashboard | Велика дата, час, привітання за часом доби, короткий підсумок дня. **Day Orb** — кругова шкала поточного режиму (виконані справи, кроки ранку або стан перевірок) з безелем доби: 24 години, події дня і точка «зараз». Під ним — **«Твоя наступна дія»** з причиною пріоритету, часом, великою кнопкою, «Відкласти» і «Пріоритет». Нижче — хронологія дня. |
| **Ранок** — Morning Flow | «ВИХІД 07:35» великими цифрами і скільки лишилося. Вертикальна шкала кроків: виконане спокійне, поточний крок підсвічено, майбутні — тихіше. При запізненні акцент стає янтарним і зʼявляється «Короткий сценарій» (режим «Часу обмаль»: критичні перевірки не скорочуються). |
| **Справи** — Priority Flow | Три шари: головне завдання → три пріоритети → решта за дотиком. Іконки категорій, кольори пріоритетів, шкала дедлайну з реального часу, повторювані справи, кроки справи, режим **«Фокус»** (одна справа, наступний крок і велика кнопка). Обовʼязкові справи не зникають, доки не виконані. |
| **Екіпірування** — Readiness Map | Кільце з пʼяти сегментів: підзвітне майно, особисте спорядження, медичний і тривожний рюкзаки, звʼязок і живлення. Статуси: без недоліків / є недоліки / потребує перевірки / перевірка триває. Перевірку можна завершити лише після позначення кожного предмета. Історія перевірок: дата, тип, результат, недоліки. Термін придатності предметів. |
| **Швидко** — Command Deck | Шість плиток: домедична, тактична, вогнева підготовка (організація занять), терміновий виїзд, несподіване доручення, власні сценарії. Плитка розгортається в чекліст; «Готово» — лише після підтвердження всіх обовʼязкових кроків, інакше «Частково». |
| **Швидко → Інструменти** — Personal Launcher | Сітка великих іконок: улюблені, категорії, пошук, додавання й зміна. Посилання перевіряються; недійсні — сірі й не відкриваються. |
| **Режими дня** | Автоматично (за часом і ранковим планом) або вручну: Ранок, Сьогодні, Готовність, Відпочинок — до кінця дня чи до скасування. Режим змінює акценти, Day Orb і порядок наступних дій. |

Дві теми: **Obsidian** (основна, темна) і **Daylight** (тепла світла). Перемикаються в налаштуваннях (⚙︎).

## Оновлення з першої версії (з iPhone)

1. Розпакуйте архів у «Файлах» — зʼявиться папка з 29 файлами.
2. Відкрийте репозиторій `opora365` на github.com → «Add file» → «Upload files» → виберіть **усі файли** з папки → «Commit changes». Файли з тими самими назвами замінюються.
3. Необовʼязково: видаліть старі `view-today.js` і `view-musts.js` (файл → «…» → «Delete file»). Вони більше не використовуються.
4. Зачекайте 2–3 хвилини: GitHub Pages публікує сайт не одразу. Готовність видно за зеленою позначкою ✓ біля останнього коміту.
5. Оновіть сторінку в Safari (потягніть донизу) або закрийте застосунок свайпом у перемикачі програм і відкрийте з іконки. Перехід з першої версії автоматичний: за кілька секунд сторінка сама перезавантажиться в ОПОРА 365, а справи, обовʼязкові й ранковий план перенесуться.

### Якщо не оновилося

1. Перевірте, що біля останнього коміту зелена ✓ (вкладка «Actions» → «pages build and deployment»). Поки там жовтий кружечок — сайт ще старий.
2. Safari: оновіть сторінку ще раз через 5 секунд. Застосунок з іконки: закрийте свайпом і відкрийте знову — просте повернення з фону оновлення не перевіряє.
3. Якщо внизу є смужка «Доступна нова версія… Оновити» — натисніть «Оновити».
4. У новій версії: ⚙︎ → «Перевірити оновлення».

Якщо застосунок ще не встановлено: «Settings» → «Pages» → «Deploy from a branch» → `main` / `(root)`. Адреса: `https://spartanetsd.github.io/opora365/`. Шляхи відносні, тож назва репозиторію може бути будь-якою.

## Наступні оновлення

1. Змініть потрібні файли й завантажте їх так само.
2. У `sw.js` збільште версію: `const VERSION = 'opora-2.0.2';` (і за бажання `VERSION` у `app.js`).
3. Після публікації застосунок покаже «Доступна нова версія ОПОРА 365 → Оновити» — під час запуску або повернення в застосунок. Перевірити вручну: ⚙︎ → «Перевірити оновлення».

Service Worker кешує всі файли разом: якщо якийсь файл не завантажився, нова версія не активується, і застосунок продовжить працювати на попередній.

## Встановлення на iPhone

1. Відкрийте адресу в **Safari** → «Поділитися» → «На початковий екран» → «Додати».
2. Запускайте ОПОРА **з іконки**. Перший запуск — з інтернетом, далі застосунок відкривається офлайн.

> Сховища Safari і встановленого застосунку на iOS окремі: дані, додані у вкладці Safari, не зʼявляться в застосунку з іконки.

## Дані, міграція, резервні копії

- Дані: IndexedDB і синхронна копія в localStorage. Схема даних має версію (`v: 2`) і перевіряється при кожному завантаженні та імпорті.
- **Міграція з v1:** при першому запуску нової версії дані v1 спершу зберігаються як є (окремий запис), потім переносяться. Копію «до оновлення» можна експортувати: ⚙︎ → «Дані до оновлення 2.0».
- ⚙︎ → «Створити резервну копію» → «Зберегти у Файли». «Перевірити резервну копію» показує вміст, нічого не змінюючи. «Відновити з копії» замінює дані, одразу після цього можна натиснути «Повернути». Копії v1 теж приймаються.
- Якщо видалити іконку з початкового екрана, iOS зітре дані. Робіть копію хоча б раз на тиждень — нагадування про це зʼявиться серед наступних дій.
- **Не завантажуйте файли резервних копій у публічний репозиторій.** Типові переліки екіпірування й сценаріїв — загальні, без службових даних; свої назви й примітки ви вносите лише на пристрої.

## Нагадування: чесно про обмеження iOS

Встановлений з Safari вебзастосунок не може сам надіслати сповіщення, коли закритий: для цього потрібен сервер Web Push, якого тут свідомо немає. Нагадування всередині застосунку (наступна дія, прострочене, перевірки, резервна копія) працюють, коли ви його відкриваєте.

Щоб не проспати: «Команди» → «Автоматизація» → «+» → «Час доби» (час підйому) → «Запускати одразу» → дія «Показати сповіщення» з текстом «Відкрий ОПОРА».

## Перевірка і тести

- На iPhone: відкрийте `https://spartanetsd.github.io/opora365/tests.html` (або ⚙︎ → «Тести логіки в цьому браузері»).

## Відомі обмеження

- Сповіщення при закритому застосунку неможливі без сервера (див. вище).
- Тактильний відгук: на Android — через Vibration API; на iPhone офіційного API немає, використовується системний перемикач iOS 18+, який може не спрацювати. Вимикається в налаштуваннях.
- Колір рядка стану iPhone для теми Daylight застосовується після перезапуску з іконки.
- Дані живуть на одному пристрої: синхронізації між пристроями немає — переносьте резервною копією.
- Перехід плитки в чекліст і ореол Day Orb вимикаються, якщо в iOS увімкнено «Зменшення руху».
- Інструменти — це посилання: сайти потребують інтернету, а їхня доступність не перевіряється (перевіряється лише формат адреси).
- Історія зберігає останні 200 перевірок і 60 запусків сценаріїв; виконані справи — 30 днів.

## Безпека

- Політика CSP дозволяє лише власні файли: жодних зовнішніх скриптів, шрифтів і запитів.
- Service Worker кешує тільки файли застосунку; особисті дані в кеш не потрапляють.
- Увесь текст користувача екранується; імпорт перевіряє й очищає дані; посилання приймаються лише https, http, mailto, tel, sms.
- Час рахується за поясом Europe/Kyiv незалежно від налаштувань пристрою.
